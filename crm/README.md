# Система заявок (CRM) «Авто-Вираж»

Перенесена с системы заявок автошколы «Сто дорог» (ветка `claude/leads-crm-849c4e`, коммит `715c09e`, 16.11.2026)
и настроена под Вираж. PHP 8.1+ без фреймворков, база SQLite (`storage/database.sqlite`; MySQL — по желанию, `DB_DSN`).

## Что умеет

- **Приём заявок** с форм сайта: `POST /api/lead` и старый адрес `/send-form.php` (контракт — `docs/lead-api.md`).
  Ловушка для ботов, лимиты с IP и на номер, повторная заявка с того же номера добавляется к первой.
  Номера заявок продолжают счётчик старого сайта (`LEADS_FIRST_ID`).
- **Письмо о заявке** на почту школы — тема прежняя: «ID: N. Новая заявка с сайта Вираж», в конце ссылка на карточку.
- **Админка `/crm`**: заявки с фильтрами, «Кому звонить» (очередь по графику попыток), карточка заявки (статусы
  «Беру / Не дозвонился / Думает / Придёт на договор / Записан / Отказ / Мусор», комментарии, ответственный,
  напоминание, путь клиента по сайту), «Заходы» на сайт, отчёты, настройки текстов и режима работы, сотрудники, журнал действий.
- **Счётчик заходов** — свой, `assets/js/visits.js` на всех страницах (`/api/visit`, формат — `docs/visits-api.md`); заявка связывается с заходом. Яндекс Метрика остаётся.
- **Оповещения**: Telegram без персональных данных (номер заявки, услуга, ссылка), бот MAX для администраторов и клиентов —
  **выключены, пока не заданы токены** в `.env` (инструкции — `cron/README.md`).
- **Планировщик** (`cron/run.php` раз в минуту): напоминания, повторные попытки, «не дозвонились», отчёты, удаление
  заявок без записи через 12 месяцев (152-ФЗ). **Копии базы** — `cron/backup.php`, 14 дней.

## Что выключено у Виража

- **SMS** — `SMS_DRIVER=off`: ничего не отправляется и в истории не пишется, раздела SMS в настройках нет.
  Подключить: `SMS_DRIVER=p1sms` (или `smsru`), ключ и имя отправителя в `.env`. SMS уходят только на мобильные номера;
  заявки с городских (3822…) принимаются.
- **Чат-бот на нейросети** (DeepSeek) — не используется: у сайта свой помощник на готовых ответах (`assets/js/bot.js`).
  Код остался, пункта «Чат» в админке нет, пока не задан `DEEPSEEK_API_KEY`.

## Где что лежит

| Где | Что |
|---|---|
| `crm/` в репозитории → `~/virazh-crm` на хостинге (вне сайта) | код, шаблоны админки, миграции, cron, `.env`, `storage/` (база, логи, копии) |
| `root/crm.php` → корень сайта | вход: находит `~/virazh-crm` и передаёт запрос; `/send-form.php` просто подключает его |
| `.htaccess` (собирает `tools/build.pl`) | `/crm…`, `/api/lead`, `/api/visit`, `/max/webhook` → `crm.php`; другой PHP на сайте не запускается |
| `assets/js/site.js` | формы шлют заявку на `/api/lead` и после ответа ведут на `/spasibo` |

## Хостинг (только после «да» владельца на перенос)

Всё делает `tools/deploy.sh` (описание — в его начале):

- `stage` — код в `~/virazh-crm-new` (без `.env` и `storage/`) и прогон тестов на сервере; рабочий сайт не меняется.
- `switch` — новый код получает `.env` и `storage/` прежней версии; при первом разе создаётся `.env`
  (`APP_ENV=production`, `MAIL_DRIVER=mail`, случайный `LEADS_SECRET`, `LEADS_FIRST_ID` = counter.txt Joomla + 1),
  `php database/migrate.php`, в `crontab` **добавляются** две строки (задания «Сто дорог» не трогаются, копия — `~/deploy-upload/crontab-*.bak`):

```
* * * * *  /opt/php/8.3/bin/php /var/www/u1605290/data/virazh-crm/cron/run.php >/dev/null 2>&1
40 3 * * * /opt/php/8.3/bin/php /var/www/u1605290/data/virazh-crm/cron/backup.php >/dev/null 2>&1
```

- `check` — кроме адресов сайта проверяет `/api/lead`, `/api/visit`, `/crm`.

Первого руководителя создаёт владелец сам (пароль вводит он): `php ~/virazh-crm/database/create-manager.php логин "Имя"`.
Остальных сотрудников руководитель добавляет в админке. MAX и Telegram включаются токенами в `~/virazh-crm/.env` (`cron/README.md`).
